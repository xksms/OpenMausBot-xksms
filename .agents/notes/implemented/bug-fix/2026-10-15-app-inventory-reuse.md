# Agent Note: 应用连接状态优先复用已有结果

Status: implemented

## Problem

连接状态已经持久化到浏览器，弹窗的初始阶段却只判断模块内存是否存在。渲染器重载后，旧结果虽然能显示账号，所有普通应用按钮仍等待网络检查。检查没有总超时，而服务端可能连续查询会话与多页账户，导致反复打开时长时间不可操作。

## Decision

连接状态先从持久化结果恢复，已有结果立即用于展示与操作。五分钟内的完整结果直接复用；过期结果留在页面，网络在后台更新。等待授权中的记录跳过有效期，手动刷新始终请求服务端，并发检查合并为同一请求。

检查请求总超时为十秒。没有任何历史结果时，失败进入不可用状态并提供重试；有历史结果时，保留账号并标记结果未能确认。只有服务端成功检查才更新时间，读取、打开页面与局部轮询不会延长完整清单的有效期。机器人实际调用继续读取服务端实时状态。

## Alternatives considered

- 每次打开都检查可以获得最新清单，但会让界面交互受外部服务延迟影响。
- 隐藏检查并立即把未知应用当作未连接可以消除等待，却会误导已有账号的用户；首次无缓存仍保留未知状态。
- 无限期复用结果可以完全消除重复请求，但外部断开账号后不能及时反映状态。

## Consequences

普通打开最多复用五分钟前的展示状态，用户可通过刷新立即更新。授权和断开仍由原有服务端接口校验，后台失败不会清空账号。真实首次检查可能等待最多十秒，随后可重试。
