# Agent Note: 应用分类菜单的边界与本地化

Status: implemented

## Problem

应用弹窗裁切子元素，向右对齐的宽分类菜单会越过左边界，长列表的末尾也无法访问。连接服务的分类名包含小写、连字符和 `&`，与本地翻译表的固定大小写不同。

## Decision

应用分类菜单显式启用 SidebarPopoverMenu 的 portal，使用视口坐标定位，优先在触发器下方展开；空间不足时在上方展开，列表高度限定为可用空间并允许滚动。原有聊天区的内联菜单和个人菜单的默认位置不变。菜单内的 Escape 只关闭菜单并归还焦点。

分类名称仅在显示时规范化，再查本地化键；筛选仍使用服务返回的原始分类值。产品名称保持原名，已知应用简介使用本地语言，未知分类和简介保留服务原文。

简介的后续展示规则由[动态应用目录的中文覆盖](2026-10-15-app-catalog-chinese-coverage.md)部分替代；菜单布局和筛选身份规则继续适用。

## Alternatives considered

- 取消弹窗的 overflow-hidden 可以直接显示菜单，但会破坏圆角边界，仍然无法约束长列表的高度。
- 将所有向下展开的菜单统一迁移到 portal 可以减少模式，但会扩大到聊天区的悬停与焦点交互。本次只为应用分类启用。
- 翻译服务返回的分类值可以让显示直接使用中文，但会改变筛选身份；显示层映射保留原始标识。

## Consequences

应用弹窗使用独立浮层，因此需要同时验证点击、滚动、键盘选择、Escape、窗口缩放和边界。动态新分类在未加入翻译表前仍显示原文。验证使用临时数据目录与合成目录，不访问用户的应用连接或账户。

## Testing

`docs/verification/app-categories.md` 提供可重现的隔离页面。相关五个测试文件覆盖分类名规范化、已知与未知简介、上下方空间约束、菜单焦点与 Escape 隔离，以及原有筛选和菜单行为。
