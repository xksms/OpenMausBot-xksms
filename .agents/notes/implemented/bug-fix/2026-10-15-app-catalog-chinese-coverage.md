# Agent Note: 动态应用目录的中文覆盖

Status: implemented

## Problem

实际目录包含 1,608 个应用和 101 个分类。有限的固定词表使较低位置的分类与大部分第三方简介继续显示英文；只用少量合成类别验证无法发现覆盖缺口。

## Decision

`src/lib/app-catalog-copy.ts` 集中管理分类和简介。分类词表覆盖捕获目录中的全部分类，常用应用及截图应用提供具体中文简介；其余应用显示明确标为“用途”的中文分类摘要，不把它伪装成原简介的逐字翻译。原始说明保留在简介提示中，状态提示不混入第三方原文。其他语言继续沿用各自翻译和服务原文。

产品名称、分类筛选值与连接标识保持原值。元数据样本仅包含公开分类及 94 个常用应用，测试按提供方词汇检查覆盖。隔离页面也支持载入已捕获的完整目录元数据。

这部分替代[应用分类菜单笔记](2026-10-15-app-categories-menu.md)中“未知简介保留原文”的展示决定；浮层位置与键盘约束继续适用。

## Alternatives considered

- 继续逐个补充截图词汇可以提供精确简介，但不能覆盖动态增加的大目录应用，容易再次出现相同遗漏。
- 运行时在线翻译可以翻译新增简介，但会增加网络依赖、等待时间和费用。本地分类摘要立即可用，并明确保留原文供核对。
- 隐藏所有未翻译简介可以保持页面语言一致，但用户缺少判断应用用途的信息。

## Consequences

目录普通展示具备中文用途说明，具体翻译仍优先于摘要。摘要只表达已知分类，不表达提供方原文的全部细节。新增分类仍需扩充词表；快照测试能发现已捕获词汇的回归，不能证明未来上游词汇已翻译。原文提示可能包含英文，这是用户主动查看的来源信息。

## Testing

`src/lib/app-catalog-copy.test.ts` 检查 101 个分类、94 个具体简介、动态分类摘要、原文提示、已有中文和其他语言的行为。`docs/verification/app-categories.md` 描述如何用完整捕获目录验证真实页面。
